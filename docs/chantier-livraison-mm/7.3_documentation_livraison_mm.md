## 1. Ce qui change par rapport à l'original de ce sprint

L'original demandait une réécriture assez large de `CLAUDE.md` (« V4 »,
supposant un document resté figé sur les intentions initiales). Ce n'est
plus le cas ici : `CLAUDE.md` a été amendé **au fil de l'eau** pendant les
chantiers MM.0–MM.14 (section 3 déjà réécrite pour l'architecture modulaire,
RG-12 déjà reformulée pour le rattrapage, mention du Sprint MM.14 déjà
présente). Repartir d'une réécriture complète referait un travail déjà
fait. Ce sprint corrige des **écarts précis**, vérifiés avant rédaction :

| Section | Écart constaté | Ce qu'il faut faire |
|---|---|---|
| §3 (packages) | Liste 6 modules métier — le 7ᵉ, `notifications` (extrait au Sprint MM.13), n'y figure pas | Ajouter `notifications` à la liste, avec sa raison d'être (découplage AFTER_COMMIT des envois) |
| §13 (authentification) | Toujours intitulée « simulation en développement », sans mentionner que `JwtUtil`/`AuthService` ont été supprimés et que Keycloak (réel, local) est l'unique émetteur depuis MM.7 | Réécrire pour refléter l'état réel : Keycloak local via `docker-compose`, Authorization Code + PKCE, résolution d'identité par email (décision I-2) |
| §16 (ordre des sprints) | S'arrête à « Sprint 7 : Tests d'intégration, recette, corrections, README » — ne mentionne ni le chantier modulaire (MM.0-MM.14) ni le chantier design (D.0-D.4) | Ajouter un paragraphe (pas une réécriture) resituant ces deux chantiers après le Sprint 7 original, avec leurs dates et leur objet en une ligne chacun |
| Aucune section dédiée | Le nombre d'endpoints (34 dans la version d'origine, §8) a changé : MM.9 à MM.13 ont ajouté des endpoints (`/ecarts-montants`, `/en-attente-crh`, rattrapage, etc.) sans que §8 soit mis à jour | Recompter les endpoints réels dans le code (pas dans un document), mettre à jour §8 |

Le reste de `CLAUDE.md` (règles métier RG-01 à RG-12, conventions de code,
charte visuelle) est déjà à jour — **ne pas le toucher** sans écart constaté
et montré.
