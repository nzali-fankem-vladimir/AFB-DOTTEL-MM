## 3. Écarts et observations

### 3.1 Aucun correctif de code requis

Tous les scénarios ci-dessus sont **conformes**. Aucune anomalie fonctionnelle
n'a été détectée dans le code applicatif pendant cette recette.

### 3.2 Deux fausses alertes, imputables à l'outillage de test (pas au code)

Deux 500 ont été observés pendant la recette en environnement de shell Windows
(Git Bash) lors de l'envoi de motifs accentués via `curl -d` avec le caractère
intégré directement dans la commande. Investigation :

- Trace serveur : `HttpMessageNotReadableException: JSON parse error: Invalid
  UTF-8 middle byte`.
- Reproduction avec le même contenu envoyé via un **fichier UTF-8 propre**
  (`curl --data-binary @fichier.json`) : **succès, 200/201**, y compris avec
  des caractères accentués (« Écart tarifaire non justifié », « Chargé de
  Clientèle »).
- Conclusion : Git Bash sur Windows corrompt l'encodage des caractères non-ASCII
  passés en littéral dans `-d`. Le backend traite correctement l'UTF-8 dès lors
  que les octets envoyés sont corrects. **Aucune action requise côté DOTTEL.**

Observation mineure et non bloquante notée au passage : quand le corps JSON
reçu est réellement invalide (comme dans le faux positif ci-dessus),
`GlobalExceptionHandler` renvoie 500 (« Une erreur interne est survenue ”)
plutôt que 400, faute de gestionnaire dédié à
`HttpMessageNotReadableException`. Un vrai client (navigateur, `fetch`/`axios`)
ne produit jamais d'UTF-8 invalide, donc ce chemin n'est pas atteignable en
usage normal — signalé pour information, pas proposé en correctif dans ce
sprint (hors périmètre : recette et backlog réel uniquement).

### 3.3 Constat réel, à documenter : la promotion de rôle ADMIN n'a pas d'effet tant que Keycloak n'est pas mis à jour

Point vérifié en jouant le scénario, pas supposé (comme demandé par le guide) :
`PATCH /admin/utilisateurs/{id}/role` ne met à jour **que** la table
`utilisateurs` de DOTTEL. Le rôle réellement porté par le jeton JWT (donc
effectif pour `@PreAuthorize` et tout le reste des autorisations, via
`RoleJwtAuthenticationConverter`) est **exclusivement** déterminé par les
rôles réalm attribués côté Keycloak (cohérent avec la décision P-2 du
Sprint MM.7 : Keycloak est seule autorité pour les rôles). Un nouveau login
après une promotion DOTTEL montre encore l'ancien rôle.

**Conséquence pratique pour un administrateur DOTTEL réel :** promouvoir
quelqu'un via l'écran ADMIN de DOTTEL ne change rien à ce que cette personne
peut réellement faire tant que quelqu'un (la DSI, dans le realm réel, via l'AD)
n'a pas aussi changé son groupe/rôle Keycloak. Ce n'est pas un bug — c'est la
conséquence directe et assumée de P-2 — mais ce n'était écrit nulle part avant
ce rapport. **Recommandation : documenter ce comportement dans l'écran
d'administration lui-même (ou dans son aide contextuelle) pour que l'ADMIN ne
croie pas la promotion immédiatement effective.** Décision à confirmer avec
vous avant toute modification d'écran — hors périmètre de correctif immédiat
de ce sprint (pas de nouvelle fonctionnalité).

### 3.4 Effet de bord du partage de la base de développement entre recette manuelle et `mvn test`

Après la recette manuelle, un second `mvn test` montre **289/290** au lieu de
290/290 : `IntegrationFluxMetierTest.flux1_enrolementComplet` échoue sur sa
propre précondition (« le matricule 1847 ne doit pas déjà être enrôlé »), car
la recette manuelle de ce rapport a justement enrôlé ce matricule dans la
**même** base `afb_dotations_telephoniques_mm` que celle utilisée par les
tests d'intégration. **Ce n'est pas une régression de code** — le run `mvn
test` effectué juste après l'application de V8, avant toute recette manuelle,
était bien à 290/290, BUILD SUCCESS (voir section 1). La correction propre
(retirer le bénéficiaire 1847 et ses `ligne_etat_mensuel`) impliquerait de
toucher un processus déjà CLOTURE — jugé trop risqué pour un simple nettoyage
de fixture de test. **Recommandation pour les sprints suivants** : faire
tourner la recette manuelle sur une base dédiée, distincte de celle utilisée
par `mvn test`.
